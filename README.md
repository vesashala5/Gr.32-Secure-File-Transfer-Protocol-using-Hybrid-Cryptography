Overview
This project implements a custom secure file transfer protocol over TCP sockets. It combines:

Asymmetric cryptography (RSA-2048): For key exchange and digital signatures.
Symmetric cryptography (AES-256-CFB): For efficient bulk file encryption.
Hashing (SHA-256) and RSA-PSS signatures: For integrity and authentication.

Key security features:

Mutual key exchange: Server and client exchange public RSA keys.
Per-session AES key: Generated by the client and encrypted with the server's RSA public key.
End-to-end encryption: Files are encrypted during transfer.
Server-side storage encryption: Files are re-encrypted with a dedicated AES key (protected by the server's RSA key).
Digital signatures: Client signs uploads; server signs downloads.
Integrity checks: SHA-256 hashes verified on both sides.

File Descriptions

crypto_utils.py: Core cryptographic functions using the cryptography library.
RSA key generation, serialization, loading.
RSA-OAEP encryption/decryption (for AES keys).
AES-256-CFB encryption/decryption (with random IV prepended).
SHA-256 hashing.
RSA-PSS signing and verification.

protocol.py: Defines the wire protocol for reliable messaging.
Message format: 16-byte tag (padded) + 4-byte length + data.
Chunked file transfer support (CHUNK = 4096).
Helper functions send_msg() and recv_msg() with recv_all() for reliability.

server.py: Listens on 127.0.0.1:5001.
Manages persistent server RSA key pair.
Handles key exchange, upload, and download.
Stores files encrypted with per-file AES keys (AES key itself encrypted with server RSA public key).

client.py: Interactive CLI for uploading or downloading files.
Generates temporary RSA key pair per run.
Performs hybrid key exchange.
Signs uploads and verifies server signatures on downloads.


How It Works
1. Key Exchange (Hybrid)

Server sends its public RSA key.
Client sends its public RSA key.
Client generates a session AES-256 key, encrypts it with the server's public key, and sends it.
Server decrypts the session AES key with its private key.
Both now share a secure session AES key for the connection.

2. Upload Flow

Client: Reads file → Computes SHA-256 → Signs hash with client's private key → Encrypts file with session AES → Sends chunks.
Server: Receives → Decrypts with session AES → Verifies signature & hash → Generates new per-file AES key → Re-encrypts file for storage → Encrypts the file AES key with server's RSA public key → Saves both.

3. Download Flow

Client requests filename.
Server: Loads encrypted file + encrypted AES key → Decrypts AES key with server private key → Decrypts file → Signs hash with server private key → Re-encrypts with session AES → Sends.
Client: Decrypts with session AES → Verifies server signature & hash → Saves file.

Installation & Usage
Prerequisites

Python 3.8+
cryptography library: pip install cryptography

Running the Server
Bashpython server.py
First run generates server_private.pem and server_public.pem.
Running the Client
Bashpython client.py
Choose:

Upload file (provide local path)
Download file (provide filename stored on server)

Test files: prova1.txt, prova2.txt, prova3.txt are included for quick testing.
Features & Design Decisions

Persistent server keys: Ensures the server can decrypt previously stored files across restarts.
Double encryption on upload: Protects files at rest independently of transfer encryption.
Chunked transfer: Handles large files efficiently without loading everything into memory.
Error handling & verification: Failures (bad signature, hash mismatch, missing files) are clearly reported.
Local-only: Runs on localhost by default (easy to change HOST/PORT).

Security Considerations
Strengths:

Hybrid encryption (best practice for performance + security).
Forward secrecy elements per session (new AES key each connection).
Authenticity via signatures.
Protection against tampering (hashes + signatures).

Limitations / Notes (for educational / assignment context):

No perfect forward secrecy (server RSA key is long-term).
No authentication of client identity beyond per-session signatures.
No TLS — this is a custom protocol for learning purposes.
Private keys stored without password protection.
Runs on localhost by default.
